# Tokens

Never commit credential values. Store each credential in the secret system used by its consumer. For local runs use the Git-ignored root `.env`; for production use backend Fly secrets. For manual operator scripts use a protected shell environment. None belong in browser code or user sandbox configuration.

## Fly sandbox-management token

**Name:** `FLY_API_TOKEN`

**Purpose:** Allows the backend to create/manage sandbox Apps, Machines, private networks, and optional volumes, and collect provider telemetry/logs.

**Storage and use:** Backend Fly secrets; root `.env` for local cloud-backed testing. It needs access to the organization in `FLY_ORG` and the dynamically created sandbox apps. A token limited to deploying the control-plane app is insufficient. Sandbox agents receive their own generated credential, never this token.

## Manual backend deployment

Use your authenticated Fly CLI operator identity, or set the Fly CLI's `FLY_API_TOKEN` in a protected operator shell with access to the target app. The removed workflow's `FLY_DEPLOY_TOKEN` Actions secret is no longer consumed. Keep deployment credentials separate from the backend's sandbox-management token.

## Tigris access keys

**Names:** `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`

**Purpose:** Authenticate backend reads, writes, and garbage-collection deletes for workspace objects.

**Storage and use:** Backend Fly secrets; root `.env` locally. Scope credentials to the irv bucket. Set the non-secret bucket, endpoint, and region settings described in [settings.md](settings.md).

## Database password

**Name:** `DATABASE_PASSWORD`

**Purpose:** Authenticates the backend to PostgreSQL.

**Storage and use:** Backend Fly secrets; root `.env` for Compose/local runs. Use the existing database's actual password when connecting to an already provisioned database. The generated password initializes the bundled Compose database only when its data volume is new.

## MFA encryption key

**Name:** `IRV_ENCRYPTION_KEY`

**Purpose:** Encrypts enrolled second-factor secrets in the database.

**Storage and use:** Backend Fly secrets; root `.env` locally. Generate 32 random bytes encoded as Base64 with `scripts/init_env.py`. Keep a protected backup alongside your database recovery procedure. Replacing this key alone makes existing encrypted factors unreadable; key rotation requires data re-encryption, which this release does not automate.

## Initial administrator invite

**Name:** `IRV_BOOTSTRAP_INVITE`

**Purpose:** Creates the first administrator signup invitation.

**Storage and use:** Generated by `scripts/init_env.py`; store in backend Fly secrets for initial production setup. Enter its value in the signup form, create a username/password, then complete MFA. It is single-use and expires 24 hours after the backend first inserts it into that database. Remove it from Fly secrets and your local environment after setup.

Changing the variable or restarting does not renew an existing expired bootstrap invite: the backend will not insert another while an admin invite row or admin account exists. An expired unused bootstrap invite needs an operator database intervention. Do not delete an established database just to regenerate an invite.

**Later invites:** An authenticated administrator creates them in Administration or with `POST /api/admin/invites`. They are single-use, default to 24 hours, and accept `hours` from 1–168 (values are clamped). The app returns the raw code when generated and stores its hash. List with `GET /api/admin/invites`; revoke with `DELETE /api/admin/invites/{hash}`. These codes need no additional environment variables. They create ordinary user accounts, which must enroll MFA.

## Image-promotion token

**Name:** `IRV_MAINTENANCE_TOKEN`

**Purpose:** Authorizes manual selection of image digests through the maintenance endpoint. The endpoint does not test or scan images itself.

**Storage and use:** Backend Fly secrets; generated in root `.env` locally. Use distinct values for staging and production. For a manual image-catalog change, supply the target backend's value as `MAINTENANCE_TOKEN` in the operator shell running `scripts/promote.py`. No matching GitHub Actions secrets are required.

## SMS verification — optional

**Names:** `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_VERIFY_SERVICE`

**Purpose:** Configure Twilio Verify SMS second-factor enrollment/login. `TWILIO_VERIFY_SERVICE` is the Verify Service SID.

**Storage and use:** Backend Fly secrets; root `.env` for intentional SMS tests. The auth token is secret; the two SIDs identify the account/service and are kept with this configuration. Leave all three empty when using only TOTP. Microsoft Authenticator and Duo Mobile TOTP need no vendor API key.

## Staging smoke-test account

**Names:** `IRV_SMOKE_USERNAME`, `IRV_SMOKE_PASSWORD`, `IRV_SMOKE_TOTP`

**Purpose:** Allow the manually invoked `scripts/live_smoke.py` to log in and check the sandbox lifecycle.

**Storage and use:** Protected operator shell environment. Also set `IRV_SMOKE_ORIGIN` to the staging backend URL. Use a dedicated staging account. `IRV_SMOKE_TOTP` is its enrolled Base32 authenticator secret, not a six-digit code. Anyone with the password and this secret can authenticate as that account.

## Removed workflow configuration

The removed workflows no longer consume `FLY_DEPLOY_TOKEN`, `IRV_STAGING_MAINTENANCE_TOKEN`, `IRV_PRODUCTION_MAINTENANCE_TOKEN`, `IRV_PRODUCTION_ORIGIN`, `IRV_STAGING_APP`, or `IRV_PRODUCTION_APP`. The bundled app requires no GitHub Actions secrets. Keep the backend's runtime secrets and any credentials used for manual scripts.

## Updating credentials

Replace provider credentials in every consumer that uses them, verify access, then revoke the old provider credential. Change promotion tokens in the backend and any manual operator configuration together. Updating `.env` does not update an already deployed app. The encryption key needs the special migration procedure described above.
